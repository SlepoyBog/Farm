# AI Content Farm

Автоматизированный Python-конвейер, который выбирает тему, создаёт и проверяет материал с помощью LLM, публикует адаптированные версии в нескольких каналах и собирает метрики для следующих итераций.

> **Статус:** проект приостановлен. Автоматический запуск по расписанию отключён; ручной запуск сохранён.

Публичный результат: [AI-блог на GitHub Pages](https://slepoybog.github.io/Farm/).

## Что реализовано

- генерация и дедупликация тем по нишам;
- создание, критика и исправление статей через DeepSeek API;
- проверка структуры и безопасное сокращение HTML;
- отдельное форматирование для сайта, Telegram, VK, OK и Dzen;
- SEO-метаданные, Open Graph, sitemap и RSS;
- отложенная публикация и устойчивое локальное состояние;
- сбор метрик, health report и feedback loop;
- GitHub Actions: тесты, генерация, recovery-артефакты, GitHub Pages и публикация;
- ручной recovery workflow для подготовленной публикации.

## Масштаб проекта

- 24 Python-модуля и около 4 800 строк Python;
- 13 тестовых модулей и 55 тестовых сценариев;
- 497 сгенерированных HTML-страниц в текущем публичном снимке;
- более 600 коммитов, включая автоматические контрольные точки состояния;
- период активной разработки: май — октябрь 2026 года.

## Архитектура

```text
Тренды / очередь тем
        ↓
LLM: план → статья → критика → исправление
        ↓
Валидация HTML и SEO
        ↓
Статический сайт → GitHub Pages
        ↓
Telegram / VK / OK / Dzen
        ↓
Метрики → health report → рекомендации
```

Состояние сохраняется атомарно. Перед внешней публикацией GitHub Actions создаёт recovery-артефакт; при сбое подготовленный материал можно восстановить отдельным ручным workflow.

## Личная роль

Моя роль: идея и постановка задачи, проектирование рабочего процесса, управление разработкой через AI-инструменты, проверка кода и результатов, настройка GitHub Actions, тестирование, эксплуатация и разбор сбоев.

Файл `AGENTS.md` описывает **AI-роли**, использованные для разделения разработки, ревью, QA, DevOps и аналитики. Это не список сотрудников или реальная команда из десяти человек.

## Технологии

Python 3.11, asyncio, REST API, DeepSeek API, Telegram Bot API, VK API, GitHub Actions, GitHub Pages, JSON, HTML/CSS, RSS, sitemap и Prometheus client.

## Локальный запуск

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m unittest discover -v
.\.venv\Scripts\python.exe src\main.py
```

Для запуска генерации нужен как минимум `DEEPSEEK_API_KEY`. Каналы публикации можно подключать независимо через переменные окружения.

## CI/CD

Основной workflow находится в `.github/workflows/publish.yml`. Он запускается вручную через `workflow_dispatch` и выполняет:

1. установку зависимостей и тесты;
2. генерацию и сохранение состояния;
3. создание recovery-артефакта;
4. развёртывание сайта на GitHub Pages;
5. публикацию в подключённые каналы;
6. обновление аналитики и health report.

## Безопасность

- секреты не хранятся в репозитории и передаются через `.env` или GitHub Secrets;
- `.env`, журналы и локальные выгрузки исключены из Git;
- опубликованные аналитические файлы заменены демонстрационными данными;
- `.env.example` содержит только пустые значения и безопасные настройки.

## Ограничения

- качество материалов зависит от выбранной модели и промптов;
- внешние API могут менять лимиты и форматы ответов;
- перед публикацией в новом канале необходимы ручная проверка и настройка прав;
- проект демонстрирует инженерный конвейер, а не редакционную экспертизу по всем представленным темам.
